# store: one Postgres layer, pgx, embedded migrations

## Context

Services must not pick drivers or migration tools ad hoc. A second
dialect or a migration state outside the binary makes replay and audit
impossible.

## Decision

`shared/store` is the only Postgres access layer. The driver is pgx
(`database/sql` via `pgx/v5/stdlib`); `shared/store/admin` uses the
same driver for install-time administration. Migrations are embedded
`NNNN_name.sql` files, gap-free from 0001, applied inside one
transaction under `pg_advisory_xact_lock`, each recorded in
`schema_migrations` with a sha256 of its body. An applied file whose
hash changed is refused. An N-1 binary may read an expanded schema
whose applied migration numbers are contiguous and whose known prefix
hashes match. Tests get temporary schemas in the same container.

## Rejected

- golang-migrate / goose: migration state and ordering live outside
  the binary and allow gaps and edits.
- lib/pq alongside pgx: two drivers is two dialects; owner decision
  fixes one.

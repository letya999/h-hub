# fsm: one transition, CAS, deadline on every non-final state

## Context

v0 lost updates through flag-style state writes and copied sweep logic
in several places. One mechanism, one table, one transition is the
fix.

## Decision

`shared/fsm` owns all state machines. `fsm.machines(kind,id)` holds
state, deadline, actor, version. `Transition` runs in the caller's
transaction: optimistic CAS `WHERE state=? AND version=?`, a history
row with actor and reason, outbox effects, and an optional hook — all
atomic. A forbidden edge writes nothing; a CAS loser gets `stale`.
Every non-final state arms a deadline naming its sweep event and next
actor; `LongLived` states are explicit and never swept. The sweeper
reads a narrow due projection, re-verifies inside its own write
transaction, and skips rows that moved on. `fsm.sweeper_leases` is an
atomic owner+expiry upsert that elects the sweeping instance.

The v1.0 sweeper model is one sweeper per service. The lease row is
keyed by sweeper name only (primary key `name`); sharded leasing is
not designed (owner decision, phase 2 closeout).

## Rejected

- `SELECT ... FOR UPDATE` as the arbiter: it serializes actors and
  hides lost-update bugs instead of surfacing `stale`.
- Per-service state tables and sweep copies: v0's failure mode.

# Бриф фазы 1 (0.0.1): репозиторий и гейты

Цель фазы - пустой по доменному коду репозиторий h-hub, в котором с первого
коммита работают все проверки, а каждая проверка доказана падением на
сломанном примере. Код сервисов в этой фазе не пишется.

## Источники (читать только их)

- `h-hub-AGENTS.md` - кладётся в корень h-hub как `AGENTS.md`, `CLAUDE.md` -
  симлинк на него.
- `00-summary/enforcement.md` разделы 1-5 и 7-8 - точные пороги и проверки.
- `00-summary/h-hub-blueprint.md`: раздел 2 (вводная, правила границ),
  2.13 (shared, contracts, hubctl), 7 (ресурсный бюджет), 9 (фаза 1).
- `00-summary/owner-decisions.md` - только при споре о пороге или правиле.

Код hermes-hub не открывать и не копировать.

## Что сделать

0. Рабочее место - Windows, исполнение - Linux. Репозиторий -
   `C:/Users/User/a_projects/h-hub`. Dev-образ `hhub-dev` (Go, golangci-lint,
   gitleaks, just, linters) по digest; `just check` на Windows (`windows-shell`
   pwsh, не Git Bash) запускает его с исходниками только для чтения и кешами
   Go и линтеров в томах Docker; внутри контейнера тот же `just check` идёт
   как в CI. Никаких `*_windows.go`, `.ps1` и записей в Windows-папку из
   контейнера.
1. Layout: `cmd/hubctl/`, `cmd/hubctl/install/`, `services/` (пусто),
   `shared/` (только `store/admin`), `contracts/` (пусто), `tools/archtest/`,
   `tools/descriptor/`, `adr/`, `docs/phases/`, `deploy/`, `testdata/broken/`.
   Один Go-модуль, версия Go и toolchain закреплены в `go.mod`.
2. `just check`: golangci-lint v2 с конфигом из `enforcement.md` раздел 2;
   depguard по разделу 3; `tools/archtest` (AST-проверки раздела 3);
   gitleaks по всей истории; гейт размера файлов в git (~256 КБ); линтер
   миграций expand/contract; docs-гейт (AGENTS.md до 150 строк, шаблон
   README, ссылки на тесты существуют); гейт `trace` (пока пустая матрица,
   но ссылка на несуществующий ID - падение); проверка «fix без
   изменённого теста». Быстрая часть - pre-commit.
3. Мета-тест: каждый линтер из списка включён и каждый порог задан.
4. Дескриптор сервисов `deploy/descriptor.yaml` и его схема: сервис, образ,
   зона, рёбра с операциями, env (до 10 `HHUB_*`), потолки mem/cpu/pids,
   тома. Без потолков или со слишком большим env - отказ валидации.
   `tools/descriptor` генерирует `deploy/compose.yaml` (сейчас - только
   Postgres); сгенерированный файл лежит в git, гейт проверяет, что он
   совпадает с генерацией.
5. Postgres: контейнер `postgres:17-alpine` по digest, mem_limit.
6. `hubctl init` (пакет `cmd/hubctl/install`, через `shared/store/admin`):
   id установки и каталог конфигурации вне томов Docker; ключи Ed25519 для
   сервисов дескриптора и оператора; KEK для `shared/seal`; базы, роли и
   схема `fsm` для сервисов дескриптора. Идемпотентно: повтор доделывает
   недостающее и никогда не перезаписывает ключи, KEK и id установки.
7. `hubctl doctor` - только чтение: дескриптор валиден, файлы ключей и KEK
   на месте с правильными правами, базы и роли совпадают с дескриптором, id
   установки совпадает. Проверка Docker появится вместе со spawn-controller.
8. Защиты от болей v0:
   - отказ путей Windows и артефактов MSYS (каталоги вида `x;C`, `C:Users`);
   - запрет `.json`/`.jsonl` файлов состояния и слов `legacy`, `compat`,
     `fallback`;
   - модуль `github.com/letya999/hermes-hub` запрещён;
   - cron-workflow без алерта на падение - отказ;
   - бюджет диска Docker для dev-машины: потолок кеша сборки и проверка
     `just devenv` в `tools/` (не продукт и не вторая система проверок);
   - проба размера образа подключается в фазе, где появляется первый образ
     сервиса.
9. GitHub Actions: один workflow, один итоговый обязательный статус,
   dependabot сгруппирован по экосистемам, CODEOWNERS на `adr/`, конфиги
   линтеров и гейтов, `deploy/descriptor.yaml`.

## Сломанные примеры

Для каждого гейта - каталог `testdata/broken/<гейт>/` с минимальным
нарушением и тест, который ждёт падения гейта на нём: файл 501 строка,
функция 61 строка, 21 метод, 6 параметров, запрещённый импорт, `os.Getenv`
вне config, `exec.Command`, `time.Sleep` и `t.Skip` в тесте, слово `legacy`,
`.json`-файл состояния, дескриптор без потолков и с 11 env, миграция с
`DROP` без `contract-of`, файл больше 256 КБ, тестовый секрет для gitleaks,
каталог `x;C`, импорт модуля hermes-hub, AGENTS.md на 151 строку,
cron-workflow без алерта, ссылка `trace` на неизвестный ID.

## Готовность

- `just check` зелёный локально (Windows -> dev-контейнер) и в CI,
  укладывается в 5 минут локально; если нет - записать замер в отчёт как
  сигнал пересмотра (запасной путь - клон в ext4 WSL).
- Каждый гейт падает на своём сломанном примере, мета-тест зелёный.
- `hubctl init` дважды подряд даёт то же состояние; `hubctl doctor` после
  него зелёный и красный, если удалить файл ключа или роль.
- Тег `v0.0.1`.
